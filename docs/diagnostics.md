# Client diagnostics

The endpoint is disabled unless its runtime flag is enabled. The frontend sends only fixed categories, at most once per category per page load. It does not send input, page URLs, query strings, error messages, stack traces, user IDs or cookies. Failed delivery is ignored without retrying.

Categories: `render` (error boundary), `operation` (unhandled promise), `offline` (worker registration), `update` (activation failure), `hydration` (recoverable React hydration error), `browser_app` (runtime error with a same-origin script filename), `browser_external` (runtime error with a different HTTP(S) origin), and `browser_unknown` (missing, opaque or unparseable source). Source classification happens locally; the filename is never transmitted. `browser` remains accepted for old cached clients. A same-origin filename is an attribution clue, not proof of the cause; cross-origin scripts may hide their source. Historical `browser` rows cannot be reclassified.

Counts represent received, deduplicated events, not distinct visitors or an error rate. Delivery and rate limits can omit events. Keep production and preview separate; synthetic validation events must be documented when interpreting small counts.

Bind Cloudflare Analytics Engine as `DIAGNOSTICS_STATS`, dataset `letraspro_diagnostics`, in both deployment environments. Each accepted event writes one point: `index1` and `blob1` contain the fixed category, `blob2` is `production` or `preview`, and `double1` is 1. Dataset timestamps are generated by Cloudflare. Storage failure does not change the endpoint's 204 response. No public statistics-reading endpoint or API credential is added.

Cloudflare currently retains Analytics Engine data for three months: https://developers.cloudflare.com/analytics/analytics-engine/limits/. Inspect the dataset in the authenticated Cloudflare dashboard. Account access is required; the user requested dashboard statistics without email alerts. For sampled data use weighted counts:

```sql
SELECT blob1 AS category, blob2 AS environment, SUM(_sample_interval * double1) AS errors
FROM letraspro_diagnostics
WHERE timestamp >= NOW() - INTERVAL '7' DAY
GROUP BY category, environment
ORDER BY errors DESC
```

Before enabling on Cloudflare Pages:

1. Verify `/api/diagnostics` on a preview deployment, with the runtime variable `DIAGNOSTICS_ENABLED=true`. A same-origin JSON POST with `{"code":"render"}` must return 204. Cross-origin requests must return 403; disabled endpoints return 404.
2. Configure the desired log retention, sampling and abuse limits in Cloudflare. `_routes.json` limits function invocation to this endpoint, keeping pages and static assets on static serving.
3. Check the site's privacy notice against the actual hosting and diagnostics configuration. Cloudflare may retain request metadata separately from the fixed application log.
4. Set the **build** variable `VITE_DIAGNOSTICS_ENABLED=true`, rebuild and validate one diagnostic from the preview site. Runtime and build flags are separate so collection cannot start accidentally.
5. Verify the Analytics Engine dataset receives a synthetic preview event and returns its fixed category and environment. Pages real-time logs alone do not constitute persistent statistics. Do not enable email alerts unless the user separately requests them.

To stop collection, remove the runtime flag immediately, then remove the build flag and rebuild. These controls do not change the converter's input, saved data or URLs.
